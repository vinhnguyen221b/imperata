# Images of the guides

The diagrams and the screenshots here are generated by scripts, in English (`.en`). Change the scripts in `src/` and run them again rather than editing an image. The illustrations at the end were drawn by an image model and hold no text.

## Run board screenshots (WebP)

Taken by `src/screenshots.mjs` from the real board, rendered over two **synthetic** runs of a fictional product, TeamLeave (`src/sample-runs.mjs`). They show no real product, person or data.

| File | Shows |
| --- | --- |
| `board-overview.*.webp`, `board-overview-dark.*.webp` | The overview: what waits on the owner, then every run (light and dark theme) |
| `board-questions.*.webp` | Question cards of a run, one answered, the next one open, the meter |
| `board-reply-preview.*.webp` | The reply the Orchestrator will receive |
| `board-approval-card.*.webp` | An approval card for the specification, locked while questions are open |
| `board-markdown-page.*.webp` | A run document opened as a readable page from the board server |
| `board-tasks.*.webp` | Tasks in waves with complexity, model and steps done |
| `board-traceability.*.webp` | Acceptance criteria traced to tasks and tests, one criterion opened to its cases |
| `board-run-acceptance.*.webp` | A run ready for acceptance, with the acceptance card |
| `board-phone.*.webp` | The decisions of a run on a phone |

```bash
node docs/images/src/screenshots.mjs                 # all of them
node docs/images/src/screenshots.mjs --only tasks    # the ones whose name contains "tasks"
```

They are WebP at quality 90 (`--quality` changes it): under half the size of the same shots as PNG, with text as sharp at full size. GitHub, VS Code and current browsers show WebP.

The script installs the kit into a scratch repository in the system temp folder, writes the sample runs, starts `scripts/board-server.mjs` and drives a headless Chrome through its DevTools protocol. It needs Node 22 or later and Chrome (found at `CHROME`, else at the usual macOS and Linux paths), downloads nothing and removes the scratch repository at the end. Retake the screenshots when the board changes, and check them before committing: the selectors in `screenshots.mjs` follow the board's markup.

## Illustrations (WebP)

Six decorative drawings, `art-*.webp`, made with an image model (GPT Image 2.5 Sunburst, OpenAI) and released with the rest of the repository under its MIT license. Each is a drafting sheet pinned on a blueprint board, in ink on bone-white paper with red as the only accent: the colors of `brand/`. They carry no information: everything a reader needs is in the text, the diagrams and the screenshots, and each has an `alt` text.

| File | Shows | Used in |
| --- | --- | --- |
| `art-team.webp` | The owner at a board of cards, and a tall robot with a baton leading six small robots with the tools of their trades; studies of the robot above them | Top of `USER_GUIDE.md` and of `README.md` |
| `art-understand.webp` | A robot explaining a path with flags to two others | `USER_GUIDE.md`, Part 1 |
| `art-set-up.webp` | Robots carrying a crate of tools into a small house with a folder-shaped roof | `USER_GUIDE.md`, Part 2; `README.md`, "Quick start" |
| `art-first-run.webp` | Robots passing a parcel through three gates, a person at the middle one | `USER_GUIDE.md`, Part 3; `README.md`, "What a run looks like" |
| `art-other-ways.webp` | A fork in a path: a scooter, a net and a beetle, a map | `USER_GUIDE.md`, Part 4 |
| `art-reference.webp` | A small library | `USER_GUIDE.md`, Part 5; `README.md`, "Documentation" |

No script regenerates them: a model draws something new each time. The briefs, the model and what was done to the files afterwards are in [`src/illustrations.md`](src/illustrations.md). Check a new drawing by eye before it replaces one: no text, an empty title block, no logo, no figure that looks like a character of a game or a film, and the same style as the others.
